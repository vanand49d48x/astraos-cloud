End-to-End Workflow: Request LifecycleIntegrating satellite data with ASTRA OS follows a standardized five-step lifecycle. This process ensures that regardless of whether the data comes from Sentinel, Landsat, or Planetary Computer, the developer experience remains consistent.Step 1: Discovery (Unified Search)The workflow begins by defining an Area of Interest (AOI).What it contains: A bounding box (bbox), a datetime range, and a cloud_cover_lt threshold.Action: Call astra.search(). The API queries all live catalogs and returns a list of matching "Scenes".Step 2: Inspection (Scene Metadata)Before processing, you must evaluate the returned scenes to ensure they meet your quality standards.What it contains: Complete STAC metadata, including the provider-scoped ID, exact time of capture, and cloud percentage.Action: Review the metadata for specific parameters like Sun Elevation or Data Quality bits.Step 3: Resolution (Asset Selection)Once a scene is selected, you resolve the actual data files (bands).What it contains: Direct, secure URLs for specific spectral bands (Red, Green, Blue, NIR) in Cloud-Optimized GeoTIFF (COG) format.Action: The Asset Resolver automatically routes your request to the correct cloud storage bucket without you needing to manage individual provider credentials.Step 4: Execution (Asynchronous Processing)For compute-intensive tasks, ASTRA OS uses an asynchronous job pattern.What it contains: A processing request (e.g., ndvi()) that is enqueued as a background Task.Action: The system returns a Task ID. You can poll the status endpoint to track progress from Queued to Processing and finally Completed.Step 5: Delivery (Download & Analysis)The final step is retrieving the analysis-ready data.What it contains: A final .tif file that has been orthorectified and standardized to a common grid.Action: Download the output for use in your GIS application, or feed it directly into a downstream machine learning pipeline.10.
